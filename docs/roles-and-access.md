# 角色职责与最小知情访问

## 角色职责

| 角色 | 主要职责 | 明确不得承担 |
|---|---|---|
| **监护人 guardian** | 提交申请、签署授权、登记/变更接送人、确认临时接送、同意外出与家访、取消报名、安全事件共同处置 | 查看其他家庭信息 |
| **持证社工 certified_social_worker** | 资格审核与定级、家访（主责）、安全线索研判升级与处置、敏感资料保管 | —（敏感数据的主要被授权方） |
| **团干部 league_cadre** | 点位统筹、班次与风险复核、排班审核、跨点调班与任务认领调度、案件指派协调 | 查阅与其点位服务无关的家庭详情 |
| **点位负责人 site_lead** | 当日签到签退、接送核验、外出带队、人员缺勤上报、安全线索首报与现场先期处置 | 自行处置升级案件、查阅保障原因详情 |
| **高校志愿者 volunteer** | 完成基础培训后承担普通陪护、协助签到秩序、发现线索及时报告 | **心理团辅、急救值守、家访、单独带队、接触家庭敏感档案** |
| **课程方 course_provider** | 按课程清单授课、课程器材风险说明 | 查看保障原因、接送名单、案件、联系方式以外的家庭信息 |
| **企业/园区主办方 enterprise_host** | 提供场地、容量变更、因征用取消班次 | 查看儿童与家庭明细、排班人员资质详情 |
| **运营人员 operations_staff** | 入点/等待队列操作、排班协调、通知触达、状态跟踪看板 | 查看保障原因详情、家访与案件内容（只见状态） |
| **市级项目组 city_project_team** | 用去标识数据评估覆盖率与服务连续性、政策调整 | 直接调取可识别个人数据 |
| **系统 system** | 到期预警、资质拦截、等待队列递补、补签对账、留存冻结、去标识发布 | — |

## 数据分级

- **operational**：完成职责所必需的状态（班次、容量、排班状态、签到结果、接送确认结果、案件状态/级别）。
- **restricted**：家庭敏感资料——保障原因、监护授权与接送人身份、家访安排与记录、安全线索内容。仅向**实际服务该儿童**的持证社工开放（`actor.serving_child_ids` 命中）；团干部/点位负责人在履职必需时可见其中的接送与安排字段，不可见原因与案件内容。
- **sealed**：升级后的安全案件与证据记录。仅主办社工及法定需要的角色可见；系统强制不可删改、到期冻结。

## 执行要点

1. **服务关系校验前置**：每次读 restricted/sealed 字段，除角色外还要校验当前在册服务关系（社工主办/家访关系），关系结束即收回。
2. **课程方与企业收到的是投影视图**：课程方只见所授课程的上课名单（不含保障原因），企业只见点位容量与取消等运营通知，不获得儿童与家庭明细。
3. **运营只见必要状态**：案件看板对运营仅暴露 `case_id`（内部流水）、`status`、`severity`、是否需要协调资源；`content_ref` 等引用对其不可解析。
4. **默认拒绝**：矩阵未覆盖的组合一律不可见；扩大授权须由社工或团干部在事件流中留痕。
5. **去标识出口唯一**：市项目组的数据只经 `DEIDENTIFIED_DATASET_RELEASED` 获得，使用稳定化名 ID 做跨周关联，不导出原始标识。
